So… what is IT, in one minute?

Information technology (IT) is the study and use of computers, networks, and other devices to create, process, store, retrieve, and send information. When a school keeps grades in a system, when a store scans your items, when you message a friend — IT is the machinery and the know-how behind all of it.

IT is an application of computer science and computer engineering: part building things, part fixing things, part helping people use them. The full guide breaks every piece down — hardware, software, code, networks, data, security — in simple order.

1958

The term “information technology” first appeared in print in a Harvard Business Review article — the field is younger than your grandparents.

Everything a computer does — photos, songs, games — is stored and processed as binary: long strings of just two digits.

Hello, World! — First Code

Almost every programmer’s first program does one small thing: it prints the words Hello, World! It looks too easy to matter — but it proves your setup works, and it shows the basic shape of all code: instructions go in, a result comes out.

What happens when code runs

Every program — this tiny one, and the biggest game — follows the same three steps.

1

You write

You type instructions into a file. That file is your program — a list of orders the computer follows exactly, in order.

2

You run it

A tool turns your file into actions. An interpreter translates and follows your instructions as it goes. A compiler translates the whole file first, then runs the translation.

3

You see the output

The result appears — that is the output. If you can read Hello, World!, your tools work and you just ran a program.

What is IT?

The short version, then the real one.

Information technology (IT) is the study or use of computers, telecommunication systems, and other devices to create, process, store, retrieve, and transmit information. That’s the textbook definition — here’s what it means in real life:

  • Create — typing a document, taking a photo, writing code.
  • Process — a computer doing something with data: computing your grades, editing your video, running a game.
  • Store — saving files on a drive, in a database, or in the cloud.
  • Retrieve — opening that file later, searching for a record, loading a saved game.
  • Transmit — sending information across networks: messages, video calls, this web page reaching your screen.

An IT system is the whole setup working together — all the hardware, software, and connected equipment, used by a group of people. A school’s enrollment system, a bank’s app, a hospital’s records: each is an IT system.

IT vs. Computer Science — what’s the difference?

They overlap a lot. Roughly: computer science studies how computing works in theory — algorithms, math, how to design new systems. IT applies it — setting up, running, securing, and supporting the systems people actually use every day. In college, BSIT leans practical: programming plus networks, databases, and systems administration.

The computer system

Hardware you can touch, software you can’t — and how they work together.

A computer system has two halves. Hardware is every physical part. Software is the set of instructions (programs) that tell the hardware what to do. Hardware without software is a paperweight; software without hardware has nowhere to run.

The main hardware parts

CPU — the brain

The Central Processing Unit does the actual computing: billions of tiny calculations per second. When a game says it needs a faster processor, this is the part it means. Its speed is measured in gigahertz (GHz).

RAM — short-term memory

Random Access Memory holds what you’re working on right now — open apps, the game you’re playing. It’s fast, but it forgets everything when the power turns off. More RAM = more things open at once without slowing down.

Storage — long-term memory

Hard drives (HDD) and solid-state drives (SSD) keep your files even when the computer is off. SSDs have no moving parts and are much faster — that’s why a laptop with an SSD boots in seconds.

Motherboard — the backbone

The big circuit board everything plugs into. It connects the CPU, RAM, storage, and all other parts so they can talk to each other, and carries power and data between them.

Input devices

How information gets in: keyboard, mouse, touchscreen, microphone, camera, scanner. Your taps and keystrokes become data the computer can process.

Output devices

How results come out: monitor, speakers, printer, headphones. The graphics card (GPU) deserves a mention too — it’s a specialized processor that draws everything on screen, crucial for games and video.

The two kinds of software

System software

The software that runs the computer itself. The biggest piece is the operating system (Windows, macOS, Linux, Android). It manages the hardware, runs your apps, and handles files. Utilities like antivirus software belong here too.

Application software

Programs you use to do tasks: browsers, Word processors, games, photo editors, messaging apps. Apps sit on top of the operating system — they ask the OS whenever they need the hardware.

How a computer actually works, step by step

1

Input

You press a key, tap the screen, or open a file. The instruction and data enter the computer.

2

Fetch

The CPU fetches the next instruction from RAM — the instruction for whatever program is running.

3

Decode & execute

The CPU decodes what the instruction means, then executes it: add two numbers, compare values, move data. This fetch–decode–execute cycle repeats billions of times per second.

4

Memory

While working, data sits in RAM for speed. Results you want to keep get written to storage (SSD/HDD) so they survive a shutdown.

5

Output

The result appears: pixels on the monitor, sound from the speakers, a printed page — or a message sent across the network.

Every app you’ve ever used — from a calculator to a full game — is just this cycle happening unimaginably fast.

Binary: how computers represent everything

Computers are built from tiny switches that are either on (1) or off (0). Each switch is one bit. Eight bits make a byte. Numbers, letters, colors, sounds — all of it gets converted into patterns of bits. The letter “A”, for example, is stored as the number 65, which in binary is 01000001.

Coding / programming

Writing instructions a computer can follow — exactly, literally, every time.

Code is a set of instructions written in a programming language. A computer does exactly what the code says — no guessing, no common sense. Programming is mostly problem-solving: break a big task into small, exact steps, then write those steps in a language the computer understands.

The four building blocks of all code

Variables

Named boxes that store values. score = 0 makes a box called score holding 0. Later the code can change it: score = score + 10.

Conditions

Decisions. If something is true, do this; else, do that. Like: if the password is correct, log in; else, show an error.

Loops

Repetition without copying code. “Repeat 10 times” or “keep going while lives remain” — loops are how a game checks your controls 60 times a second.

Functions

Reusable mini-programs with a name. Write greet(name) once, then call it whenever you need it, with any name. Functions keep big programs organized.

Your first Python program

# This is a comment — the computer ignores it
name = input("What is your name? ")   # variable + input
score = 0

for i in range(3):                    # loop: repeats 3 times
    score = score + 10                # function of the loop body

if score >= 30:                        # condition
    print("Great job, " + name + "!")
else:
    print("Keep practicing, " + name + ".")

That tiny program already uses all four building blocks. Almost every program ever written is these same ideas, scaled up.

The web: how websites work

What actually happens between typing an address and seeing a page.

Client vs. server

Your browser is a client — it asks for things. A server is a powerful computer, always on, whose job is to answer those requests: it stores the website’s files and data and sends them to whoever asks. Every website you visit lives on a server somewhere.

Front-end vs. back-end

Front-end = everything you see and tap in the browser (HTML, CSS, JavaScript). Back-end = the behind-the-scenes part on the server: the code (PHP, Python, Node) and the database that handles logins, posts, payments, and saved data.

Loading a website, step by step

1

You type an address

e.g. example.com — a friendly name, because humans are bad at remembering numbers.

2

DNS looks up the number

The Domain Name System translates the name into the server’s IP address — like a phonebook for the internet.

3

Your browser sends a request

Using HTTP (or its secure version, HTTPS), your browser asks the server: “send me this page.”

4

The server responds

The server may run back-end code, pull data from a database, then send back HTML, CSS, JavaScript, and images.

5

Your browser builds the page

It reads the HTML for structure, CSS for design, runs the JavaScript for interactivity — and renders what you see. All in under a second.

Internet & networking

How devices connect, find each other, and exchange data.

A network is simply two or more devices connected so they can share data. The internet is a giant network of networks — millions of smaller networks all agreeing to speak the same languages (protocols) so data can travel between any of them.

LAN vs. WAN

LAN (Local Area Network) — a small area: your home Wi-Fi, a school computer lab. WAN (Wide Area Network) — a huge area: a company’s offices across cities. The internet is the biggest WAN of all.

IP addresses

Every device on a network gets an IP address — a unique number label like 192.168.1.5 (private, inside your home) or a public one the whole internet can reach. Data travels in small chunks called packets, each stamped with the sender’s and receiver’s IP addresses.

Router vs. switch

A switch connects devices inside one network and passes data between them. A router connects different networks together — your home router links your LAN to the internet and decides where packets go next. (Home “Wi-Fi routers” usually combine both, plus a wireless access point.)

TCP/IP & HTTP in plain words

TCP/IP is the internet’s rulebook: IP delivers packets to the right address; TCP makes sure they all arrive, in order, and re-sends any that get lost. HTTP is one specific language built on top, used by browsers and web servers. HTTPS is HTTP with encryption, so nobody in between can read it.

Databases

Where apps keep their information — organized, searchable, and safe.

A database is an organized collection of data stored electronically, managed by a program called a database management system (DBMS). Instead of scattering info across random files, a database keeps it structured so thousands of users can read and update it at the same time without it becoming a mess.

The most common kind is the relational database (an idea from Ted Codd in the 1970s): data lives in tables, like spreadsheets with rules. Each table has columns (the fields: name, age, grade) and rows (one record each: one student). Tables link to each other — a grades table can point to a student by their ID number instead of copying their whole name every time.

Asking a database a question, in SQL

-- Get the names and grades of students in one section
SELECT name, grade
FROM students
WHERE section = 'A'
ORDER BY name;

SQLite

The world’s most common database — it lives inside a single file and is built into phones, browsers, and countless apps. Perfect for learning and small projects.

MySQL

A full server database that powers a huge share of the web (it’s the classic partner of PHP and WordPress). Free and open source.

Think about it: your school’s enrollment list, a store’s inventory, the messages in a chat app — those aren’t “files.” They’re rows in database tables.

Operating systems & files

The manager of the whole computer — and how your stuff is organized.

The operating system (OS) is the layer between you and the hardware. It starts the computer, runs and schedules your programs, divides RAM and CPU time between them, controls the screen/keyboard/storage, manages user accounts and permissions, and keeps everything from interfering with everything else.

  • Windows — the most common desktop OS; what most school and office PCs in the Philippines run.
  • macOS — Apple’s desktop OS, only on Macs.
  • Linux — free and open source; runs most of the world’s servers, and is a favorite of programmers and network admins. Many flavors (Ubuntu, Debian, Fedora…).
  • Android & iOS — phone operating systems. Android is built on Linux; iOS is Apple’s.

Files and folders: everything stored is a file — a document, a photo, a program — organized into folders (directories) in a tree, starting from a root (like C:\ on Windows). The last part of a filename, the extension, hints at the file’s type: .txt, .jpg, .mp3. The full cheat-sheet of extensions is in the cheat sheets section below. The OS keeps track of where every file physically is, so you never have to.

PC building & troubleshooting basics

The hands-on side of IT — the part that makes you the family’s tech support.

Building a PC means choosing compatible parts and assembling them: case, power supply (PSU), motherboard, CPU + cooler, RAM sticks, SSD, and a GPU if you game or edit video. The core skill is compatibility — the CPU must match the motherboard’s socket, the RAM must match its generation (DDR4 vs DDR5), and the PSU must supply enough watts. Parts mostly click into place; the golden rules are: don’t force anything, and discharge static (touch something metal) before handling components.

The troubleshooting mindset

  1. Identify the symptom exactly. “No display” is different from “no power” — and when did it start?
  2. Check the simple things first. Cables, power, is it muted, is Wi-Fi on, did it update last night? Most “broken” PCs fail here.
  3. Restart. Genuinely fixes a large share of problems by clearing stuck states.
  4. Change one thing at a time and test — swap the cable, try a different port, boot in Safe Mode. If you change five things, you’ll never know which one worked.
  5. Read the error message and search it word-for-word. Someone, somewhere, has had the exact same problem.
  6. Back up before big fixes. Data first, experiments second.

Ethical hacking & cybersecurity

Yes — hacking is a real IT career. The legal, professional kind.

Hacking, in its original meaning, is deeply understanding a system well enough to make it do things — or reveal weaknesses its makers didn’t notice. Whether that’s good or evil depends entirely on permission and purpose:

Black hat

Breaks into systems without permission — to steal, damage, or extort. This is crime, not a career.

White hat (ethical hacker)

Hired, with written permission, to attack a system on purpose — find the holes first, report them, and help fix them before criminals find them.

Security researcher

Studies vulnerabilities and publishes findings responsibly so software gets patched and everyone’s systems get safer.

What ethical hackers actually do

A penetration tester (“pentester”) is hired by a company to try to get in — through the network, the website, sometimes even by testing whether employees fall for fake emails. Every attempt is agreed in advance, documented, and ends in a report: here’s the hole, here’s how bad it is, here’s how to fix it. The job is maybe 20% “attacking” and 80% understanding systems deeply and writing clear reports. It requires strong foundations first — networking, Linux, and coding — which is why it sits near the end of the Course on this site.

How to practice legally

  • Your own devices and your own lab — an old laptop, virtual machines on your PC. Yours = legal playground.
  • TryHackMe — guided, beginner-friendly rooms built exactly for learning this legally.
  • Hack The Box — practice machines designed to be broken into, on purpose.
  • CTF competitions (Capture The Flag) — puzzle-style security contests run by schools and communities, online and in person.

The legal line — read this part carefully

Breaking into systems or accounts that are not yours, without permission, is a crime in the Philippines under RA 10175, the Cybercrime Prevention Act of 2012 — even if you “didn’t do anything” once inside, and even if it started as a joke. Ethical hacking is defined by permission + fixing, always. If you’re curious (good!), channel it into the legal practice platforms above — that’s genuinely how professionals start.

Defense basics everyone should know

  • Strong, unique passwords — long passphrases, a different one per account, ideally kept in a password manager.
  • Turn on two-factor authentication (2FA) — even if a password leaks, your account stays locked without the second code.
  • Spot phishing — messages creating panic (“your account will be deleted!”), sender addresses that are almost-right, links asking you to “log in again.” Go to the real site yourself instead of clicking.
  • Know the malware types — virus (attaches to files), worm (spreads by itself), trojan (fake useful program), ransomware (locks your files for money), spyware (watches and steals). Defense against all of them starts below.
  • Update everything — most updates are plugging holes attackers already know about. Old, unpatched software is the #1 way in.
  • Back up important files — a copy somewhere separate (external drive or cloud). Backups turn a ransomware disaster into an inconvenience.

Cloud computing basics

“The cloud” is just someone else’s computers — rented over the internet.

There is no magic cloud. When your file is “in the cloud,” it physically sits on a server in a data center owned by a company like Google, Microsoft, or Amazon. Cloud computing means using computing power, storage, or whole programs over the internet instead of only on your own device.

  • Cloud storage — Google Drive, OneDrive, iCloud: your files, reachable from any device.
  • Cloud apps (SaaS, “Software as a Service”) — Gmail, Google Docs, Canva: the program runs on their servers; you just use it in a browser.
  • Cloud servers (IaaS, “Infrastructure as a Service”) — renting a whole virtual computer from AWS, Azure, or Google Cloud to host websites and apps, and scaling it up when traffic grows.

Why companies love it: no buying hardware upfront, pay as you grow, and your site survives your own laptop dying. Why it’s a career field: somebody has to design, run, and secure all of that — that’s cloud engineering.

AI & IT Basics

What ‘AI’ actually means, where you already use it, and what’s just hype.

Artificial intelligence (AI) means getting computers to do tasks that look smart: recognizing what is in a photo, deciding whether an email is junk, or predicting the next word you are about to type.

  • Machine learning (ML) — one common way to build AI. Normally, a programmer writes every rule by hand. With ML, nobody writes the rules: the program studies many examples and finds the patterns by itself.
  • Data — the examples it learns from: emails, photos, songs, chat messages — anything it can study.
  • Training — the learning phase, when the program studies the data and adjusts itself to match the patterns it finds.
  • Model — the finished program after training. It is the thing that learned the pattern, and it now makes guesses about new things it has never seen.

Sa madaling salita: ang AI ay natututo mula sa maraming halimbawa — hindi ito binibigyan ng lahat ng sagot; hinahanap nito ang pattern.

You already use it: the spam filter

Nobody sat down and taught your email app the word “spam.” Instead, the app studied thousands of emails that people had already marked as spam, and learned which words and patterns tend to show up in them. Now, when a new email arrives, it compares the email against what it learned and guesses: spam, or not spam.

The same idea is quietly working all around you:

  • Video recommendations — the next video a site suggests is a guess based on patterns in what you, and people with similar taste, already watched.
  • Autocorrect and keyboard suggestions — your phone predicts the word you meant to type, from patterns in how people type.
  • Voice assistants — they turn your speech into words by matching the sounds against patterns learned from huge amounts of recorded speech.

Worked example: teach a tiny spam filter

Here is one simple way a model can learn. Show a program six short emails. People marked three of them as spam, and three as not spam:

What the email saysMarked as spam?
“free money now”Spam
“win a prize today”Spam
“meeting at 3pm”Not spam
“project update attached”Not spam
“free prize for you”Spam
“lunch tomorrow?”Not spam

Now the program counts — that is the whole trick. The word “free” appears in 2 of the 3 spam emails, and in 0 of the 3 not-spam ones. The word “meeting” appears only in not-spam. So the model learns a simple lean: an email with “free” is probably spam; one with “meeting” is probably fine.

Then a brand-new email arrives: “free meeting notes.” “Free” points to spam. “Meeting” points to not-spam. The model weighs the evidence on both sides and makes its best guess — a guess, not a certainty.

The key idea: the program never understood what “free” means. It never read the email the way you read it. It counted patterns, and that is all. Real spam filters study millions of emails and far more signals, but the basic idea is exactly this.

Last one: is your phone’s autocorrect a kind of AI?

Yes.

Autocorrect predicts the word you are typing — and the word you probably want next — from patterns in how millions of people type. Predicting from patterns is exactly what this whole topic is about.

Notice what all three answers have in common: the model is always guessing from patterns, never truly understanding. That leads straight to the honest version below.

The honest version — no hype

  • AI does not think. It finds patterns in data and makes guesses. There is no understanding behind the guess — just counting, done on a very large scale.
  • It is only as good as its examples. It needs lots of good data. Bad examples teach bad guesses — programmers call this “garbage in, garbage out.”
  • It can be confidently wrong. A model can state a wrong answer in a very sure voice. Always verify important answers yourself.
  • It is a tool IT people already use. Support chatbots, bank fraud alerts, tools that scan system logs for problems, helpers that suggest code — AI is already part of the job. Learning to use it well is the real skill, and it sits on top of the fundamentals: it does not make learning them pointless.

A short history of IT

Two centuries in six stops.

1843 — Ada Lovelace

The first programmer

Writing notes on a planned mechanical computer, Lovelace described an algorithm for it — an algorithm for a machine that didn’t even exist yet. She also saw, early, that computers could work with music and images, not just numbers.

1936 — Alan Turing

The idea of the computer itself

Turing described a theoretical machine that could compute anything computable — the blueprint every modern computer still follows. In WWII he helped build machines that broke enemy codes.

1940s–50s — The first electronic computers

Rooms full of vacuum tubes

Machines like Colossus (1943) and ENIAC filled whole rooms. The stored-program idea — instructions kept in memory, like data — became the standard design. In 1956, IBM shipped the first hard disk drive.

1969–80s — The internet begins

Networks learn to talk

ARPANET connected its first universities in 1969. In the 1980s the TCP/IP rules standardized everything — and in 1989–91, Tim Berners-Lee invented the World Wide Web on top of it.

1970s–90s — The personal computer

A computer on every desk

Microprocessors shrank computers from rooms to desktops. The IBM PC (1981) and early Macintosh made computing personal; Windows and the web browser brought it to everyone in the 1990s.

2007 → today — Smartphones & the cloud

A computer in every pocket

The iPhone era put a networked computer in everyone’s hand. Apps moved to the cloud, and IT quietly became the infrastructure of daily life — bills, classes, games, government, everything.

Bits and Binary: the computer’s secret language

This module’s first lesson, taught right here on the site — no other tab needed. It starts at the very bottom: the only language a computer truly understands. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

A computer does not think in words, pictures, or sounds. Deep inside, it works with electricity — and electricity in a chip is either flowing or not flowing. That is all it has. So everything a computer does must be built from just two states.

Binary is a way of writing numbers with only two digits: 0 and 1. The counting system you use every day has ten digits (0–9) and is called decimal. One single 0 or 1 is called a bit — short for binary digit. A bit is the smallest piece of information a computer can hold.

Why only two digits? A computer chip is made of billions of tiny switches called transistors. A switch has exactly two positions: off and on. Off means 0. On means 1. There is no “half-on” — and that is the point. Two very clear states are fast and hard to mix up, so a computer can flip them billions of times per second without making mistakes.

Bits usually travel in groups of eight. Eight bits together are called a byte. One byte is enough to store one character of text — the letter A, for example, is stored as the byte 01000001.

Everyday example: light switches

Think of a light switch at home. It is either off or on — never anything in between. One switch is exactly like one bit:

  • One switch (1 bit): 2 possible states — 0 (off) or 1 (on).
  • Two switches (2 bits): 4 combinations — 00, 01, 10, 11.
  • Three switches (3 bits): 8 combinations.

See the pattern? Every switch you add doubles the number of combinations. Keep doubling up to eight switches — one byte — and you get 256 combinations. That is enough for every letter, digit, and symbol on a keyboard, which is exactly why one byte can hold one character.

Sa madaling salita: ang bit ay parang switch ng ilaw — patay (0) o bukas (1) lang. At bawat dagdag na switch, dumodoble ang kayang bilangin.

Worked example 1: counting in binary

In decimal, each place is worth ten times the place before it: 1, 10, 100. In binary, each place is worth double the place before it: 1, 2, 4, 8, and so on. To read a binary number, add up the places that hold a 1. Example: 101 means 4 + 0 + 1 = 5.

5 in binary is 101, and 3 is 011. (Writing 3 as 011 changes nothing — a zero in front adds no value, like writing 03 in decimal. It just lines the columns up.) Add column by column, from right to left, exactly like ordinary addition:

   1 1       carried 1s
   1 0 1     = 5
+  0 1 1     = 3
-----------
 1 0 0 0     = 8
  1. Right column: 1 + 1 = 2. Binary has no digit “2” — 2 is written 10. So write 0, and carry the 1 into the next column. To carry means the extra value moves one column to the left — the same thing that happens in decimal when a column goes past 9.
  2. Middle column: 0 + 1, plus the carried 1, makes 2 again. Write 0, carry 1.
  3. Left column: 1 + 0, plus the carried 1, makes 2 again. Write 0, carry 1.
  4. The last carry has no column left to move into, so it becomes a brand-new column on the far left: 1.

The answer reads 1000. Check it in decimal: 1000 in binary is 8, and 5 + 3 = 8. It matches — the computer’s way and your way agree.

How computers talk: addresses and packets

This module’s first lesson, taught right here on the site — no other tab needed. It explains how computers find each other and swap information across a network. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

A network is two or more computers linked together so they can share things — files, messages, games, web pages. The internet is the biggest network of all: millions of smaller networks connected to each other.

Every computer on a network needs an address, so the others know where to send things. That address is called an IP address (IP is short for Internet Protocol — the shared set of rules computers follow when they talk to each other). No address, no delivery.

Data does not travel in one big lump. It is chopped into small pieces called packets. Each packet carries a little of the data, plus the address it is going to and the address it came from — so the pieces can find their way and be put back together at the other end.

The box that moves packets along is called a router. A router reads the address on a packet and forwards it — sends it onward, one step closer to where it needs to go. The Wi-Fi box in your home is a router.

One problem: people remember names, not numbers. So the internet has DNS (short for Domain Name System) — the internet’s phone book. You give DNS a website’s name, and it looks up the matching IP address for you.

Sa madaling salita: parang magkakapitbahay ang mga computer — bawat isa may sariling address, at ang packets ang mga sulat na ipinapadala nila sa isa’t isa.

Everyday example: sending a letter

A network works a lot like the postal service:

  • Your house address = the IP address. It tells everyone exactly where to deliver.
  • The letter you send = a packet. One piece of the message, travelling on its own.
  • The post office sorting office = the router. It reads the address and sends the letter onward, closer to its destination.

What if your letter is too long for one envelope? You tear it into pages and mail each page in its own envelope, numbered 1, 2, 3… The person at the other end puts the pages back in order and reads the whole letter. That is exactly what splitting data into packets is like.

Worked example: opening a website, step by step

Say you open a website. Here is what actually happens:

  1. You type the site’s name into your browser — a name you can remember, like a friend’s nickname.
  2. DNS looks up its IP address. The name is easy for you; the number is what computers use. The answer might be 142.250.190.14.
  3. Your request is split into numbered packets. Each packet is small, addressed, and numbered, so nothing gets mixed up on the way.
  4. Your router forwards each packet along a path toward that address. A packet may pass through several routers on the way, like a letter passing through several sorting offices.
  5. The reply packets come back. The website lives on a computer called a server — a computer whose job is answering other computers’ requests. Its reply packets travel back to you and are reassembled — put back together in order — into the page you see.

Now look closer at that address: 142.250.190.14. An IP address is four numbers, separated by dots. Each number is called an octet — oct means eight, because each one is stored as eight bits (remember bits and bytes from Module 1?). Eight bits can count from 0 up to 255, so every octet must be between 0 and 255.

Worked check: is 300.1.2.3 a valid IP address? No. The first octet is 300, and 300 is bigger than 255 — an octet can never be that large. One bad number makes the whole address invalid.

This module’s first lesson, taught right here on the site — no other tab needed. It covers the most useful idea in all of programming: keeping things in named boxes so your code can use them again. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

A variable is a named box in the computer’s memory that holds one value. Memory is the computer’s short-term workspace — where it keeps things while a program is running. You give the box a name, put a value inside it, and from then on you use the name whenever you need that value.

To put a value into a box, you write the name, then an equals sign, then the value — like age = 14. Careful: in code, the = sign does not mean the “equals” you know from math class. It means “put this inside the box.” So read age = 14 out loud as “age gets 14.”

Sa madaling salita: ang variable ay parang lalagyan na may pangalan — lagyan mo ng laman, tapos gamitin mo ang pangalan kapag kailangan mo ang laman.

Everyday example: a labeled kitchen jar

Picture a jar in your kitchen with a label that says “Snacks.” The label is the variable’s name. Whatever sits inside the jar — biscuits today, candy tomorrow — is the value.

You can empty the jar and refill it with something else. The contents change, but the label still says “Snacks.” A variable works exactly the same way: the name stays fixed, and the value inside can change whenever the program needs it to.

Worked example: your first variables

Your first web page: HTML is the skeleton

This module’s first lesson, taught right here on the site — no other tab needed. You will read a real web page line by line, then change it yourself in the try-coding box. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

A web page is a document — a file of text — that a browser reads and draws on your screen. The browser is the app you open websites with, like Chrome or Edge. You write the document; the browser turns it into the page you see.

The document is written in HTML, short for HyperText Markup Language. HTML is the skeleton of the page: it says what each part is — this is a heading, this is a paragraph — not how it looks. Color, size, and layout are a different job, done by a different language you will meet soon.

HTML is built from tags. A tag is a short label inside angled brackets, like <h1>. A tag and the content it wraps together are called an element: an opening tag, the content, and a closing tag. A heading is a title line — h1 is the biggest heading of all. A paragraph, written p, is a block of text.

Sa madaling salita: ang HTML ang kalansay ng page — siya ang nagsasabi kung ano ang bawat parte, hindi kung ano ang itsura nito.

Everyday example: building a house

Think of building a house. First comes the wooden frame — the skeleton of the house. The frame decides where the walls stand, and where the doors and windows go. Without a frame, there is nothing to build on.

HTML is that frame. It decides where each part of the page stands. The paint, wallpaper, and furniture come later — that decorating work belongs to CSS, the language that controls how a page looks. A page with no HTML is like a pile of bricks with no plan: all the pieces are lying there, but nothing holds them together.

Worked example: a complete real page

Here is a whole web page — every line of it. It is short, and it really works: a browser would draw it exactly as the walkthrough below describes. Read the code first, then the walkthrough under it.

<!DOCTYPE html>
<html>
  <head>
    <title>My first page</title>
  </head>
  <body>
    <h1>Hello, world!</h1>
    <p>This is my first web page.</p>
  </body>
</html>
  1. <!DOCTYPE html> — the first line. It tells the browser: “this is an HTML page.” It is a label for the browser, not a tag, and nothing from it is drawn.
  2. <html> — wraps the whole page. Everything else sits inside it, and </html> at the very end closes it.
  3. <head> — holds information about the page. The head is never drawn on the screen.
  4. <title>My first page</title> — the page’s name. It shows on the browser tab, not on the page itself.
  5. <body> — holds everything you actually see: the heading, the text, all of it.
  6. <h1>Hello, world!</h1> — a heading, the biggest size. “Hello, world!” is the classic first message programmers write when they try something new.
  7. <p>This is my first web page.</p> — a paragraph: one block of plain text under the heading.

One pattern to notice: every opening tag has a matching closing tag, and the closing tag carries a slash — <h1> opens, </h1> closes. Open, content, close. That is an element, every time.

The idea, in plain words

A database is an organized store of information that apps read and write. Reading means looking information up. Writing means saving new information, or changing what is already saved. The operating system: the manager inside your device

This module’s first lesson, taught right here on the site — no other tab needed. It explains the one program that runs everything else on your phone or computer. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

Start with the machine in your hand or on your desk. A device is a physical machine — a phone, a tablet, a laptop, a desktop computer. Its physical parts are called hardware: the screen, the keyboard, the battery, and the chips inside. Hardware on its own does nothing. It needs instructions before it can do a single useful thing.

A program is a set of instructions that tells hardware what to do, step by step. An app is a program built for one job you care about — sending messages, taking photos, playing a game. And a file is one saved piece of information with a name: one photo, one song, one document.

Now the star of this module. An operating system (short: OS) is a program — the first big one that starts when you switch a device on. Its job is to manage everything else: which app runs, where your files are kept, and how apps get to use the screen, the keyboard, the storage (the part of the device that keeps your files), and the camera. You never open the OS the way you open an app. It is simply in charge, all the time, behind everything you see.

You already know several operating systems, even if you never called them that. Windows runs most laptops and desktops. macOS runs Apple’s Mac computers. Linux is free, and it runs most servers — powerful computers that hold websites and apps for other computers to use. Android, the OS on most phones, is built on Linux. iOS is the OS on iPhones.

Sa madaling salita: ang OS ang manager ng device mo — siya ang nagpapasya kung anong app ang tatakbo, at siya ang nag-iingat ng lahat ng iyong files.

Everyday example: the school principal

Picture a school. The students are like apps — each one has somewhere to be and something to do. The classrooms and desks are like the computer’s memory (the workspace where work happens right now) and its processor (the part that does the actual work, following instructions). And the principal? The principal is the OS.

  • The principal decides who gets which room. The OS decides which app gets to use the processor, and for how long.
  • The principal keeps the filing room, where every student record is stored and can be found again. The OS keeps your files in storage, so any app can find them later.
  • The principal makes sure two classes never clash over one room. The OS shares the hardware fairly, so apps take turns instead of fighting over the screen, the camera, or the processor.

A school without a principal would be chaos — every class grabbing whatever room it wants. A device without an OS is the same: hardware with nobody in charge.

Worked example: what happens when you tap an app icon

You tap the icon for a game. Here is what the OS does, in order — all of it in about a second:

  1. The screen tells the OS your finger tapped. The touchscreen notices the touch and reports exactly where it landed. The OS works out which icon you meant.
  2. The OS finds the app in storage. Storage is the device’s filing cabinet: it holds every app and file, and it keeps them even when the power is off. The price of that safety is speed — fetching from the cabinet is slow.
  3. The OS copies the app into RAM. RAM is the device’s desk: a fast workspace where running apps sit. It is much faster than storage — but it forgets everything the moment the power goes off. That is why the app is copied there, not moved.
  4. The OS tells the CPU to start. The CPU is the worker — the part that follows instructions and does the calculating. The OS hands it the app’s first instructions, and the game starts running.
  5. The OS draws the app’s window on the screen. A window is the area of the screen where one app shows itself. The OS gives the game its window and paints it for you to see.
  6. The OS keeps the other apps paused in the background. Your chat app and music app do not close. The OS holds them in RAM, paused, and switches the CPU between all of them so quickly that it feels like everything runs at once. Running several apps this way is called multitasking.

Notice who did every step: the OS. The game never touched the hardware directly — it asked the manager, and the manager arranged everything.

Staying safe online: what cybersecurity really is

This module’s first lesson, taught right here on the site — no other tab needed. It explains what cybersecurity means, who the good and bad hackers are, and how to spot the most common trick used against ordinary people. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

Cybersecurity means keeping computers, phones, accounts, and data safe from people who try to steal, damage, or break into them. Your data is the information about you stored on a device or online — your photos, messages, school files, and passwords. An account is your personal space on a website or app, the one you open with a username and password — like your school portal account or your email account.

A hacker is a person who tries to get into computer systems — sometimes to protect them, sometimes to harm them. That difference is everything in this module, and it comes down to one word: permission.

A white hat hacker tests and protects systems with permission. The owner asks them to look for weak spots, so those weak spots can be fixed before anyone bad finds them. A black hat hacker breaks in without permission, to steal or damage things. Same skills, opposite sides — permission is what separates the two.

That is not just a rule of politeness; it is the law. Testing a system without the owner’s clear permission is illegal. In the Philippines, Republic Act 10175 — the Cybercrime Prevention Act of 2012 — makes unauthorized access (breaking into a system that is not yours) and online fraud crimes. Curiosity is good, and this site points you to legal places to practice it. Permission always comes first.

Sa madaling salita: ang cybersecurity ay ang pagprotekta sa iyong mga account at data — at ang pahintulot ang hangganan ng tama at ilegal.

Everyday example: a house with doors and locks

Think of your online life as a house. Your accounts are the rooms inside, and your data is everything you keep in them. Keeping the house safe works the same way online:

  • You lock your doors at night. Online, that means strong passwords — they are the locks on your accounts, so use long ones that are hard to guess.
  • You don’t hand your keys to strangers. Never share your passwords or one-time codes (the short numbers sent to your phone to prove it is really you) with anyone who asks.
  • A guard at the gate checks IDs before letting anyone in. That is what logging in does: the website checks your username and password to verify you are really you before it opens the door.

None of this needs special tools. Most online safety is ordinary habits, done every time — just like locking a door.

Worked example: spot the phishing email

Phishing is a trick: a fake message that pretends to come from someone you trust — a bank, a school, a delivery company — so you will hand over your password or your money. Here is a short fake email from a scammer pretending to be a bank. Read it, then we take it apart line by line.

From: support@secure-banko-alerts.com

Subject: URGENT: verify your account in 24 hours

Dear customer, we noticed unusual activity on your account. Your account will be closed in 24 hours unless you verify it now.

Click here to verify and type your password to keep your account open.

Now the walkthrough — three warning signs, in order:

  1. The sender’s address is not the bank’s real address. It says secure-banko-alerts.com — a made-up name that only sounds official. Always check the domain: the main part of an address, the part after the @ sign. A real bank message comes from the bank’s own domain, not a look-alike.
  2. The email creates panic. “24 hours or your account closes” is meant to make you rush before you think. Real banks do not threaten you like this — pressure is the scammer’s main tool.
  3. The link asks you to type your password on a strange page. Never do that. If you are worried about your account, close the email and open the bank’s real app or website yourself, the way you normally would. If nothing is wrong there, the email was fake.

Try it: real or phishing? You decide.

Three messages. For each one, decide first — is it safe, or is it a trick? — then tap the button to check yourself. Getting one wrong is fine; that is how the idea sticks.

A text message arrives: “Your package is waiting! Claim it here: bit.ly/free-pkg9” You are not expecting any delivery. Real or phishing?

Phishing.

You ordered nothing, and the shortened link hides where it really leads — a mystery link. Never tap it; delete the message.

A friend messages you: “What’s your school portal password? I’ll log in for you.” Your friend means well. Safe or unsafe?

Unsafe — don’t share it.

Never share passwords, even with friends. Your password is yours alone; once it leaves you, you no longer control who has it.

An email from your school’s real address reminds you about a real deadline — one you already knew about — and includes a link to the school portal. Real or phishing?

It looks legit — but use the safe habit anyway.

Math for IT: logic, algebra, and how to study them

This module’s first lesson, taught right here on the site — no other tab needed. It covers the two kinds of math IT students meet first — logic and algebra — and, just as important, how to study them so they actually stick. Read slowly. Every new word is explained the first time it appears.

The idea, in plain words

Logic is reasoning with two answers only: true and false. Something is either true, or it is false — nothing in between. Logic is the math of deciding, step by step, whether a statement is true.

You have already met logic in this course. In Module 1, you learned that a computer stores everything as bits — tiny switches that are either 0 or 1. Bits are just logic in disguise: 0 means false, and 1 means true.

And in Module 3, the Python lesson used if statements — lines that tell the program, “if this is true, do that.” Every if condition is a small logic question with a true-or-false answer. So logic is not new to you; this lesson just gives it a name and a shape.

The basic tool of logic is the truth table: a chart that lists every combination of inputs and the answer each one gives. You will read two truth tables in the worked example below — slowly, row by row.

Algebra is math with an unknown number. The unknown is usually written as a letter, most often x. Algebra is the part of math that teaches you to rearrange a problem — move things from one side to the other — until the unknown stands alone and you can solve for it. When a program computes a total price, or a game updates a score, algebra is working underneath.

In college, this kind of math — logic, plus sets (groups of things, like the set of all students in one class) — has its own subject name: discrete math. It sounds scary, but it is mostly what this lesson covers: yes-or-no questions and careful step-by-step reasoning. When you meet the name later, you will already know what it means.

Sa madaling salita: ang logic ay pangangatwiran gamit ang true at false, at ang algebra ay math na may hindi pa alam na numero.

Everyday example: the umbrella decision

Students make logic decisions like this every day, without noticing. Here is one, in everyday words:

Kung umuulan AND wala akong payong → mag-jeep ako. (“If it is raining AND I have no umbrella → I will ride a jeep.”)

Look at the AND hiding inside that sentence. Two conditions must both be true before the decision happens:

  • It is raining — true or false?
  • I have no umbrella — true or false?

If it rains but you do have an umbrella, you might just walk with it. If it is sunny, umbrella or not, you walk. Only when both conditions are true at the same time does the jeep decision happen. That is an everyday if/then sentence with an AND inside it — the same shape as an if statement in code.

Worked example: the AND truth table, row by row

Now the same idea as a small machine: a lamp wired to two switches, A and B, where the electricity must pass both switches to reach the lamp. In logic, this wiring is called AND. Here is its truth table. On means 1 (true); off means 0 (false).

Switch ASwitch BLamp
offoffoff
offonoff
onoffoff
ononON

Here is how to read any truth table, using this one:

  1. Each row is one combination. Two switches have exactly four possible combinations — off/off, off/on, on/off, on/on — so the table has four rows. Nothing is missing: every possibility gets its own row.
  2. Read each row left to right. First the inputs (Switch A, then Switch B), then the answer. Row 3, for example, says: A is on, B is off.
  3. The last column is the answer. The Lamp column tells you what that combination produces. Row 3’s answer: the lamp stays off, because the off switch blocks the path.
  4. Look for the pattern. The lamp turns on in exactly one row — the row where both switches are on. That is the whole rule: AND = output on only when ALL inputs are on.

Now change the wiring so the electricity can pass through either switch. That wiring is called OR. Same four combinations — only the answers change:

Switch ASwitch BLamp
offoffoff
offonON
onoffON
ononON

Read it the same way: one row at a time, inputs first, answer last. The lamp is on in three of the four rows — every row except the one where both switches are off — because OR = output on when AT LEAST ONE input is on.

NOT: flip the answer

There is one more basic logic word, and it is the simplest of the three: NOT. NOT flips a statement’s answer — true becomes false, false becomes true. It has only one input, so its truth table is the smallest you will ever see:

Switch ALamp
offON
onoff

Read it row by row, the same way as before: switch off → lamp ON; switch on → lamp off. Picture the lamp as a night-light that stays on until someone flips the switch — the switch being on is exactly what turns the lamp off. That is the whole rule: NOT = output is the opposite of the input.

In programming, NOT shows up everywhere: in Python, != means “not equal to”, and the word not flips a condition, as in if not finished: — “if it is NOT true that I am finished, do it again.” Same flip, same table.

Sa madaling salita: ang NOT ay pambaligtad — ang true nagiging false, ang false nagiging true.

How to study math for IT

Knowing the ideas is half the work. The other half is studying in a way that makes them stay. Three moves that work:

  1. Try the worked example yourself first. After you read an idea, close the explanation and work the example again on your own — with different numbers, or different switch settings — before looking at the answer. Struggling a little first is what makes the answer stick when you check it.
  2. Space it out. Three short sessions on three different days beat one long cram session the night before. Your brain keeps what it recalls again and again, so coming back to an idea on a new day is not wasted time — it is the method.
  3. Treat mistakes as the lesson. When a practice answer comes out wrong, do not just read the right answer and move on. Find exactly which row or step broke — the same way you debug a program — because that broken step is the thing you actually needed to learn.

Try it: predict the answer

Four quick predictions. Decide your answer first — then tap the button to check yourself. Getting one wrong is fine; that is how the idea sticks.

A lamp is wired the AND way. Switch A is on (1) and Switch B is off (0). Is the lamp on or off?

Off.

AND needs both switches on. With B off, the path is blocked — so the lamp stays off.

The same lamp is rewired the OR way. Switch A is off (0) and Switch B is on (1). Is the lamp on or off?

On.

OR needs at least one input on. B is on, and that is enough — the lamp lights.

A night-light is wired the NOT way: it stays on until the switch is flipped on. If the switch is on (1), is the lamp on or off?

NOT flips the input. The switch is on, so the lamp is the opposite — off.

Plan (b).

Spaced practice with questions beats one long reading. The brain keeps what it recalls repeatedly — three short sessions, each with trying-it-yourself, give it three chances to hold on.
